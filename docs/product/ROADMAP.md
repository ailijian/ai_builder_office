# 迭代路线与开放事项

> Status: ACTIVE · 2026-11-07 · 路线参考；具体工作按用户任务确定

## 阶段关系

| 阶段 | 验证问题 | 范围与状态 |
| --- | --- | --- |
| B1 / Living Office | 用户能否看懂目标到成果的协作闭环？ | 当前 Web 迭代主线；实现与检查见 [状态](../STATUS.md) 和 [验收记录](../web/ACCEPTANCE.md) |
| M2 / Visual Organization | 用户能否配置并掌控团队与工作方法？ | 目标 / 组织双入口、职责与授权、Team / Practice 保存复用；尚未实施 |
| M3 / Real Agent Integration | 真实执行信息能否可信地呈现协作与结果？ | 先接一个 Provider，处理授权、可观察事件和 Evidence；尚未实施 |
| M4 / Workflow Lab | 哪些配置确实改善质量与效率？ | 比较组织 / 流程版本与真实测量；长期研究 |

M2 保留精确的 2D 配置方式。M3 不假设平台公开完整子 Agent 生命周期，缺失信息标记未知或推断。M4 不把模拟时长、人数或观看时长作为效率证据。各阶段不是自动授权队列。

3D 是视觉路线，可在另行明确工作包后演进，不能成为当前 Web 功能的前置条件；不恢复已结束的 B2 S1 / S2 队列。流程与约束见 [3D 参考](../reference/3D_WORKFLOW.md)。

## 每轮验收重点

| 改动 | 应核对的结果 |
| --- | --- |
| 空间 / UI | 完整构图、统一坐标、人物比例、热点、键盘交互与受影响尺寸的实际截图 |
| Mock / 任务 | 单一状态源、审批阻断、实例生命周期、历史阅读、暂停和确定性回放 |
| 成果 / 对话 | 角色与任务对应，模拟内容和真实证据边界清楚 |
| 文档 / 素材 | 维护来源唯一，路径、链接和哈希有效，Git 范围正确 |

命令只在 [README](../../README.md) 维护；按改动风险选择检查，不把构建成功当作视觉或实际 Agent 验收。

## 尚待确定

- 下一项 Web 功能及其具体体验目标，由后续任务明确。
- 实体手机、其他浏览器和目标 GPU 的交互与性能；现有手机证据是 Chromium 仿真。
- M2 的 Team / Practice 编辑器、持久保存、权限控件与验收条件。
- M3 首个 Provider、可观察能力、鉴权、事件恢复、数据留存、成果证据及部署边界。
- 若重启 3D：人物拓扑 / 动画、目标设备预算、材料差异与生成来源 / 权利记录缺口。
- 长期角色数量、用户 Avatar、空间扩展和企业流程模拟方法；当前 B1 布局与角色配置不因此改变。

产品价值与用户研究假设只在 [产品方向](DIRECTION.md) 维护，工程状态只在 [STATUS](../STATUS.md) 维护。
