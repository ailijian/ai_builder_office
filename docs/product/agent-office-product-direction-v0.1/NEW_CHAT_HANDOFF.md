## 已确认的方向

- **定位**：面向个人与小团队的 **AI 原生可视化工作空间**；首期聚焦数字成果交付（品牌 VI、品牌网站、产品原型、AI 原生开发）。通用底层支持 Goal / Capability & Organization / Execution / Control / Evidence & Outcome。
- **用户心智**：**Goal（我要做什么）/ Team（谁来帮我）/ Practice（哪种方法值得复用）**。
- **入口**：默认目标模式：用户先说目标，系统推荐团队；保留组织模式供进阶用户自定义部门、能力、执行器和授权。用户无须扮演 CEO。
- **职责**：用户可以只保留熟悉/愿意参与的职责；角色选择不等于授权。重大范围变更、对外发布、重要预算/风险等仍需适用的人类或组织 Authority。
- **组织结构**：部门是稳定能力单元；部门负责人可绑定外部 Agent 执行器；子 Agent 是由任务动态产生的执行实例。人物和工位只是可视化表示，不应冒充真实 Agent 会话。
- **视觉**：保留 A1.1 温暖、精致 2.5D 微缩办公室；负责人按预设路线走动交接，子 Agent 在 M1 主要固定工位；不要过度投入呼吸、口型、复杂表情。
- **效率**：背后 Agent 工作组织、控制、验证和结果管理创造效率；3D 主要负责降低理解门槛、发现异常与帮助干预。可视化能否提升效率仍需研究。

## M1：原始产品里程碑设计（当前由 B1 延续）

**Living Office Demo：用 Mock 数据演示一个完整工作世界，不接真实 Agent。**

故事：用户提出“做品牌 VI + 品牌展示网站” → 模拟推荐设计部和研发部 → 两位负责人获得任务 → 研究、设计、前端、测试等动态子 Agent 出现在工位执行 → 负责人行走、讨论、跨部门交接 → 用户处理一次品牌方向关键决策 → 继续完成 → 成果台展示模拟成果与说明 → 提示可保存 Team/Practice（真正持久复用放 M2）。

必需机制：MockScenarioRunner（可回放）、统一模拟事件、Behavior Director、固定路线与交接锚点、2.5D 总览 + 2D 详情、模拟审批、成果查看。**不做：** 真实 SDK 集成、企业人效预测、复杂流程编辑器、自由漫游、电影级微动画。

## M2–M4

- **M2 可视化组织与编排**：用户调整部门/职责、授权、团队，模拟不同编排；保存并复用符合条件的 Practice。
- **M3 真实 Agent 接入**：先一个 SDK，用 Adapter 映射真实可观察事件；明确“真实观测/摘要推断/纯演示”的边界。
- **M4 工作流模拟/优化**：版本与成本、质量、人工介入对比；模拟结论不能当真实效率结论。

## 当前工程与上位边界

- 当前入口为 `web/` 图片式 B1：三负责人、三临时子 Agent、女性接待。旧 M1 和模型未随版；后续在该 Demo 迭代。3D 方向仍为 Blender / GLB / R3F，Tripo 高模为外观基准，绑定与动画仍需独立验收。
- Agent Office 当前作为阿造相关 UX/产品实验；**不能未经架构修订**将阿造现有“AI产品交付掌控系统”静默改称通用企业平台。原有源点AI产品家族架构及品牌 V4.0 冻结事实仍然有效。
- 现有品牌色/Y 形视觉 DNA、Authority、Claim/Evidence/Outcome、Source of Record 等原则持续适用。

## 新窗口起点

先读当前状态、根 README 与 B1 报告，在 `web/` 迭代。保留 Goal → Team → Execution → Decision → Outcome → Practice，不从旧计划自动启动 M2、真实 SDK 或付费 3D。三负责人坐姿待命，开始站立；子 Agent 按任务显隐。只有新的明确授权才能推进后续资产阶段。
