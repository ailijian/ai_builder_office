## 主线

**A1.1 视觉标准 → 已批准 Tripo G2.4 高精度造型母版 → 保真低模候选（G2.5a：主创网页 Smart Mesh P1.0 输出 V2，已授权 M1 候选使用，正式资产验收未完成） → 视觉和拓扑验收 → 分件与可编辑资产整理 → 骨骼、蒙皮和表情 → Blender 动作验证 → GLB 导出与压缩 → Three.js/R3F 实际加载 → 性能、动画及视觉验收。**

办公室的已批准模块继续取 OFFICE-ENV-001；M1.2 布局保持，B2.0 可在独立 S1 分支重新组织大型空间，不把旧布局视为最终造型目标。Tripo 仅在明确授权时供应单件家具或局部资产，不替换整间办公室。另已发现未登记的 19,100 triangles 整组办公室文件，见 S1 盘点；它不等于历史提及但未找到的“约 187 万面整屋高模”，不自动成为有效母版。

## 分阶段执行

1. **冻结输入与工作包。** 登记具体源 ID/哈希、范围、输出新版本路径、目标镜头与设备、验证内容。保留原始 GLB/FBX/纹理；G2.4 高模只作为造型与投射来源。未知生成参数/版权不臆造。
2. **选择低模候选。** G2.5a 已完成对主创自行提供的 **网页 Smart Mesh P1.0 重拓扑 V2** 的接收审计，见 接收评审（本地归档 / 外部参考，未随版：`docs/production/G25_V2_INTAKE_REVIEW.md`）。它已获 M1.1 / M1.2 负责人静态外观使用批准，但未获正式动画/发布批准，不认定与 API v3.0 是同一实现；原 API 提案（本地归档 / 外部参考，未随版：`docs/production/G25_ONE_CALL_PROPOSAL.md`）已停用，不补跑、不重复扣费。任何新上传或付费步骤仍须明确授权。它不是 P2 图生模型；P2 身份可能变化，不能当保真重拓扑替代。Blender 仍负责输入结构修正及后续可编辑资产工作；若需改变本次输入须先获授权并重做提案，不并行重建脸部或开启第二种候选。任何自动低模都必须与原高模逐视角对照；四边面源与三角化 GLB 分别统计。接口资料见 从属技术参考（本地归档 / 外部参考，未随版：`docs/production/TRIPO_RIGGING_REFERENCE.md`），不据参考自动启动绑定。
3. **先过视觉/拓扑关。** 检查正面、3/4、侧面、背面、Clay、线框以及实际展示尺度；重点为眼口、手指、肩肘髋膝、手与平板接触。仅减面、Voxel Remesh 或有 Quad 不证明可动画。失败则保留证据，按回退规则处理，不带缺陷进入完整动作制作。
4. **可编辑结构。** 低模身份经认可后，整理头/发/眼球/身体/手/道具的编辑边界、闭合眼睑和必要口部结构；固定单位、Root、命名节点与挂点，再做 UV、法线/AO 等烘焙。没有隐藏区证据时标出推断部分供人工审阅。输出可重开的 `.blend`，不只交付 GLB。
5. **骨骼、蒙皮、表情。** 先检查可用结构，再为当前工作包选择一个候选：已有兼容骨架优先复核；平台自动 Rig 属官方 Tripo 付费流程；Mixamo 仅在来源/上传范围已获授权且适合人体比例时用于基础骨架/动作；需要本地可控骨架时用 Rigify 或手工适配。**不强制依次跑三种工具**；任一路线都必须在 Blender 校正权重和变形，脸部支持另行验收。Snow 只供经验参考。
6. **Blender 动作验证。** 根据本轮约定检查眨眼、轻微笑、转头、抬手/持物、坐姿或行走的相关动作与极值；检查眼睑贴合、嘴角、肩肘、指关节、穿插与脚滑。自动绑定成功不等于动作自然。动作名与 morph 语义由本次 manifest 明确，不要求旧文档的三段/四段 Clip 同时制作。
7. **导出与优化。** 用资产 Skill 维护的导出路径；先导出未压缩 GLB，再验证，随后按实测预算选择压缩副本。基础 `export_glb.py` 只提供当前场景与不覆盖保证，不自动覆盖办公室修改器/切线/材质适配需求；旧 G1 专用脚本是历史配方，复用前审查输入和硬编码输出，改用独立版本。保留命名节点、骨架、morph、Clip 与未压缩基准；配置对应解码器，不默认执行会展平/合并的一键 optimize。
8. **浏览器与人工验收。** Three.js/R3F 加载实际输出；Playwright 固定镜头、viewport/DPR、时钟、动作帧和数据。分别核对材质、透明排序、阴影、动画、交互与资源成本，再由主创按 [质量关卡](QUALITY_GATES.md) 判定。未达到关卡时不更新为 Approved/Production Ready。

## 路径、命名与版本

- 当前文件不因目录规划而迁移或重命名；有效入口由资产登记定位，禁止按“最新文件名”猜母版。
- 新工作按需使用 `assets/source/characters/<asset_id>/`、`assets/source/environments/<asset_id>/`，原始外部文件继续位于 `assets/source/external/`；未获制作授权不预建空资产。
- 新导出为 `assets/exported/<asset_id>/<asset_id>_vNNN_uncompressed.glb` 与可选 `_web.glb`；源为同版本 `.blend`。评审资料可放既有 `design/` 工作目录；登记精确路径，不另复制第二套母版。
- 文件采用 snake_case，资产 ID 稳定且唯一；动作 PascalCase。旧文件（含空格）保持原名。节点/挂点变更与运行时契约同步。
- manifest 记录源 ID/哈希、工具与导出参数、单位轴向、预期节点/Clip/morph、预算口径和证据。现有 `character-base.sample.json` 是示例，不是当前人物的事实或强制动作清单。

## 材质与平台边界

以 glTF PBR 能表达的材质为 Web 基础。Base Color/Emissive 按颜色空间处理；Normal、Roughness、Metallic、AO 按数据纹理处理。程序材质、离线透射、面积灯、GI、light linking、约束/驱动器均须明确烘焙或运行时替代，不假定自动迁移。

Blender 艺术源保留高品质节点；Web 适配发生在派生版本。透明玻璃、人物皮肤及静态烘焙必须记录同镜头差异。旧 unlit 烘焙仅是静态评审方法，不能默认接收动态人物阴影；不得把整场景/人物图片平面冒充几何。任务内容与审批属于 HTML，不烘死为业务事实。

## 授权、失败回退与有限重试

- 模型生成及付费处理前核对用户已授权的输入、步骤、数量、成本上限；已有具体授权直接执行其范围，不重复索要同一许可。新步骤、超预算或新候选须再次获得授权。未授权时只整理本地证据和离线计划。
- 官方插件负责提交和追踪；超时/网络错误先核实已提交任务，不能把未知状态当失败重新扣费。CLI 缺失先报告，不能悄悄安装或另建 Tripo MCP。当前 CLI 及双渠道积分情况见 使用说明（本地归档 / 外部参考，未随版：`docs/WINDOWS_INSTALL.md`）；API 积分不足时按主创网页生成 → 本地接收审计协作，不自动转为网页代操作付费，不重复生成已提供模型。
- 默认工作包仅 **1 个候选**；本地同一缺陷最多 **1 次有原因依据的修正复验**。仍失败即停止该方法并记录。付费重试次数默认 **0**，除非用户已经授权明确次数和总预算；余额充足也不自动重抽。
- P2 身份偏移 → 拒收候选，保留母版，提出基于原高模的 Blender 局部重拓扑方案；不连续换种子猜脸。拓扑失败 → 回到局部眼口/关节结构；不继续自动 Rig。绑定失败 → 回到 rest pose/分件/权重；不靠运行时补偿掩盖。导出失败 → 修派生导出配置；不删预期 Clip。Web 失败 → 保留未压缩基准，定位解码器/材质/性能原因；不改原高模消除日志。
- 每次失败记录输入哈希、工具/版本、方法、已用次数/成本、症状、已证实原因与未证实假设、证据、回退点和重新尝试条件，写入对应实验报告并汇总到 实验结论（本地归档 / 外部参考，未随版：`docs/history/EXPERIMENT_LESSONS.md`）。没有新证据或方法改变，不重复失败实验。
- 人工评审未通过或未作出结论时停在该关；后续完整动画、三人扩展、业务开发须有单独范围授权。
