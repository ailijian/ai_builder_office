## 1. 永久不变的审美 DNA

- **主风格：** 温暖智能工作室（Warm Intelligent Workspace），精致微缩空间、高质量柔和动画电影质感，但不是儿童玩具。
- **人物：** 轻 Q 成年人，亲和而聪明；比例以已批准 G2.4 外观为准，旧 2.8–3.2 头身是概念起点，不得机械缩放已批准造型；保留 A1.1 的柔和脸部语言、立体块面发型、蓝灰休闲职业装、浅色运动鞋；不变成机器人或科幻士兵。
- **空间：** 奶油白与暖米为基底、浅木色和雾蓝灰为辅助、青绿为品牌强调；弧形外框、圆角家具、通透局部隔断、干净桌面、少量绿植；维持白天明亮柔光。
- **视觉优先级：** 真实工作动作 > 真实任务/成果 > 用户需介入状态 > 空间 > 装饰。信息焦点应该被引导，不应靠大面积发光吸引眼球。
- **禁用：** 赛博朋克霓虹、大量科幻全息屏、写实企业办公楼、儿童塑料玩具材质、浮夸夸张表情、满屏解释性文案、随机多色徽章。

## 2. 后续品牌规范：弧环品牌符号系统

建立**单一弧环（Arc-Ring）视觉语法**，由弧段、缺口、中心状态点和细腻不眩光的材质构成。不得加入互不关联的 3 个 Logo。

应用：角色胸牌/腕带、工位小型状态灯、成果台状态环、HTML 审批卡的图形边缘/图标。大小与厚度可按对象比例变更，但核心外观保持一致。

**状态语义由业务事件触发，不凭动画推测：**

| 状态 | 首选主色 | 除颜色外的辨识方式 | 动作建议 |
| --- | --- | --- | --- |
| Idle 待命 | 雾灰蓝 | 细环稳定，`待命` 文本 | 呼吸/自然待机 |
| Working 工作中 | 品牌青绿 | 弧段缓慢流动，`进行中` | 使用工具/阅读 |
| ReviewNeeded 需审核 | 暖金 | 环内固定提示点，`需审核` + 唯一结果卡 | 站起/指向成果 |
| Completed 已完成 | 清浅绿 | 完整环加勾，`已完成` | 收尾/轻微反馈 |
| Blocked 异常/阻塞 | 珊瑚橙红（仅小面积） | 断弧/叹号，`受阻` | 停止当前循环、提示原因 |
| Unknown/Disconnected | 中性灰 | 离线标识，显示未知 | 不表现为持续有效工作 |

不能只有颜色；必须有形状、文本或图标辅助。环不能作为真正的任务进度百分比，除非后端有可验证的进度信息。

## 3. 后续扩展规范：三人轻差异化

三个角色共用**一套可信赖的造型语法和兼容的基础骨架**，但不可表现为三个完全相同的人，只是复制位置。

| Agent | 面部/发型/配件建议 | 姿态与道具 | 强调色（少量） | 远景读图词 |
| --- | --- | --- | --- | --- |
| Research | 原人物作为基准，微调刘海/眉线；智能平板 | 站姿检索/筛选资料，屏幕对向任务 | 青绿 | 探索、搜集 |
| Analysis | 发型剪裁略规整，衣服增加浅蓝/深灰区域 | 坐姿对比图表、敲键盘 | 雾蓝 | 比较、整理 |
| Review | 发型或衣领轮廓略有区别，配弧环徽章 | 站在成果台旁，示意审批结果 | 暖金 | 交付、待审 |

限制：共享比例、材质质感与五官语言。**至少两处**可读差异（例如发型轮廓 + 手持道具），不能仅靠胸前小字和工位标牌区分。

请在画面真实可用尺寸（例：角色在 1080p 场景中约 140–220px 高，以及 25% 预览）检查人物轮廓和姿态；此尺寸为测试起点，不是严格设计定值。

## 4. 产品视觉边界：3D 与 HTML 交互边界

| 元素 | 归属 | 原因 |
| --- | --- | --- |
| 人物、家具、弧形墙体、电脑外框、成果台 | 真实 3D | 负责空间、动画、光照与点选 |
| 任务板的大块可视状态 | 3D 锚点 + 可替换内容贴图或 HTML 投影 | 远景读结构，内容不烘死在几何体中 |
| 任务状态标签、审批按钮、可读长文本 | React HTML | 可访问、可翻译、可点击，不让模型纹理承担文字精度 |
| 人物头顶的短状态提示 | HTML overlay 与 3D 世界坐标锚定 | 屏幕坐标随镜头变化，避让遮挡 |
| 详细报告、证据、权限、审批与拒绝原因 | HTML 侧栏/抽屉 | 可阅读且可审核 |
| 角色动作与工位灯 | 视觉状态机，监听可信事件 | 不生成虚假进度 |

A1.1 中首页的 `Review result` 概念气泡，**正式产品必须实现为真实 HTML 操作控件**，锚定到唯一的成果台，绝不能只在 GLB 贴图里画一个不会响应的按钮。

## 5. 静态画面视觉层级（复用 A1.1 主场景）

主镜头沿用批准办公室的正交相机；yaw 45°、俯角 30–40°只属早期构图建议，不覆盖现有相机。固定角色、任务板、成果台的相对关系，并为 HTML 任务卡留足安全区域。提供：

1. 空间全景：单人、高品质工位的 Hero 视角。
2. 人物近景：脸部、发型、材质与徽章的 3D 实拍渲染。
3. 单任务待审：Agent 姿态与唯一成果台的视觉动线。
4. 三人扩展：Research → Analysis → Review 的连续工作区，保留清晰通道和无遮挡人物。

在获授权的后续制作中，正式模型不必 1:1 复刻概念图中的每个小道具，但整体色彩、弧形结构、材质级别、人物比例和光影气质必须尽可能接近。

## 6. 不通过的典型信号

- 新的 Blender 图明显比 A1.1 概念图廉价，却被描述为“已达到一致品质”。
- 角色在中远景只靠标签才能区分；人物动作与业务状态矛盾。
- 用平面卡片或广告画面假装可编辑的 3D 人物。
- 把大量 UI 文字做成 Blender 几何对象并烘焙，导致不可读/不可交互。
- 满足代码编译却没有实际浏览器截图和动画验证。
- 模型的面数、贴图细节高，但轮廓/光照与主创参考不一致。

## 7. 冻结范围与例外

A1.2 不再生成 B/C 方案，不大幅更改 A1.1 的形体与气质。生产过程若发现某个设计客观上无法在目标平台以合理性能实现，应提供：原方案预览、替代方案预览、性能或兼容性证据，再决定是否变更。未经审阅不得直接降级质感。
