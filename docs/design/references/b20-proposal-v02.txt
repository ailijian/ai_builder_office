# Agent Office B2.0 — 会生长的 AI 工作群岛

**设计定位：AI-Native Living Workspace**

**方案状态：设计提案 V0.2，待主创评审**

## 01. 核心设计理念

**让用户拥有一座会根据目标组织、激活和调整工作团队的 AI 创意园区。**

传统办公室的空间由固定组织决定：设计部有多少人，就安排多少张桌子。

Agent Office 则不同。

它的工作组织会随着目标而变化。当用户提出新的目标，相关能力区域被激活，部门负责人接收任务，所需的子 Agent 按需出现，工作结束后执行席位恢复待命。

整个空间不是被动展示人物，而是让用户直观理解 AI 如何组织工作。

### 三个设计关键词

**有温度的未来感**：精致、自然、舒适，避免冰冷的科技控制室。

**动态生长的组织感**：工作空间反映当前目标与团队状态，允许未来增加能力区域。

**可观察的工作生命力**：角色与任务状态相互关联，每次走动、交接和协作都有实际含义。

## 02. 总体空间：一座约 240–320㎡ 的开放式 AI 创意园区

建议先按约 18m × 15m 的单层空间建立概念比例，实际建模尺寸可以根据镜头和角色比例调整。

采用一个整体连续的建筑空间，内部由多个具有不同功能的「工作岛」组成。

不使用真正悬浮的平台，也不设置大量高低错落的台阶。

各个工作岛通过弧形隔断、局部玻璃、地毯、植物、灯光和家具形成自然边界。

**整个空间不应像展馆里摆放的若干展台，而应该像一间设计精美、可以实际工作的未来办公室。**

### 空间结构

整体采用「中央目标中枢 + 周边能力区域 + 共享生活与协作设施」的布局。

中央负责展示目标、工作组织和重要事件；周边是能力与执行区域；接待、休息、讨论和成果交付形成独立的体验空间。

主要包含八个区域：

| 区域 | 核心功能 | 空间气质 |
|---|---|---|
| 01 目标中枢 | 目标展示、组织推荐、全局工作状态 | 标志性、清晰、智能 |
| 02 品牌设计岛 | 设计负责人及设计能力 | 温暖、创意、精致 |
| 03 研发工作岛 | 研发负责人及技术工作 | 现代、有序、专业 |
| 04 研究策划岛 | 资料研究、分析与任务规划 | 安静、专注、开放 |
| 05 子 Agent 执行岛 | 动态执行任务的工作终端 | 模块化、简洁、高效 |
| 06 协作讨论区 | 跨部门交接、讨论与决策准备 | 舒适、开放、交流感 |
| 07 休息与接待区 | 待命、迎接用户、轻量探索 | 放松、亲和、有生活气息 |
| 08 成果展示区 | 查看交付成果、证据与工作结果 | 高级、清晰、有成就感 |

这些是逻辑区域，不意味着必须建成八个封闭房间。

## 03. 空间视觉中心：Goal Hub 目标中枢

这是整个 Agent Office 最具品牌记忆点的建筑。

### 造型

目标中枢位于空间中心略偏后的位置。

使用一个直径约 3–4m 的圆角环形建筑装置，底座结合浅木、暖白石材和低饱和青绿色。

中心可以采用一块垂直信息屏或半透明展示界面，不需要一根巨大的蓝色全息光柱。

外围使用一圈克制的弧形灯带，与原 A1.1 的弧环符号形成视觉关联。

### 用户体验

无任务时，中枢安静地显示：

「准备开始新的目标」

用户创建目标后，出现：

「制作一个品牌网站」

接着目标中枢展示 AI 推荐参与的能力组织，例如品牌设计部、研发部。

相关工作岛被激活，状态连接线短暂出现，随后回到安静的工作状态。

### 最重要的设计规则

目标中枢是**整个工作的视觉入口，而不是监控所有 Agent 的大型仪表盘**。

它只显示关键目标、阶段、活跃团队和需要用户关注的事项。

复杂任务详情仍由 2D UI 承担。

## 04. 部门工作岛

### 品牌设计岛

保持 A1.1 中精致的木质桌面、柔和青绿色办公椅、白色弧形隔断。

空间面积建议约 20–30㎡。

配置一位负责人工作位、少量设计设备和设计展示板，不需要大量桌椅。

负责人负责规划和组织品牌视觉工作。

当设计任务开始时，对应工作区的任务屏亮起。

### 研发工作岛

与设计岛共享建筑语言，但使用稍微更利落的家具结构。

可以采用雾蓝灰色办公设施、较大屏幕和简洁的技术信息板。

空间面积建议约 20–30㎡。

同样只保留一个明确的负责人工作位和少量功能设备。

### 负责人专属区域

不建议将负责人放进完全封闭的传统经理办公室。

更适合采用「半独立工作舱」。

工作舱有弧形建筑边界、玻璃隔断、精致工作桌及舒适办公椅，但能从主视角看见角色。

负责人没有任务时，可以在休息区待命；收到目标后，前往自己的工作舱进行统筹；发生协作时，再前往讨论区。

M1 阶段暂时使用简化的站位与动作转场表达，不强制制作完整坐下、起立动画。

## 05. 子 Agent 执行岛

这是最应该体现 AI Native 特征的区域之一。

它不需要模拟人类公司的密集办公区。

建议设计成一个精致的「智能执行工作台」，拥有 4–6 个可扩展的终端槽位，但首版只展示实际需要的几个。

每个终端对应一次工作实例或明确标识的工作组。

### 状态设计

**待命**：屏幕暗下，设备保持低亮度。

**接收任务**：对应终端亮起，显示工作类型。

**执行中**：显示简化工作内容与状态，不要求播放复杂动画。

**任务完成**：显示完成标记，成果进入对应交付链路。

**任务结束**：终端恢复待命。

子 Agent 不需要常驻 3D 人物。

未来若需要更拟人化的角色，可以为重要执行任务显示人物形象，但不能为了让场景热闹而增加虚假的工作人员。

## 06. 独立协作讨论区

这将是目标中枢之外第二重要的空间。

建议位于中心偏前位置，占用约 25–35㎡。

设计一组低矮弧形沙发、椭圆讨论桌，以及一块能够展示当前协作内容的轻量屏幕。

与普通会议室不同，它应当看起来轻松、开放，适合短时间的任务对齐。

当 Design Lead 和 Dev Lead 需要协作时，双方从各自工作区移动至此。

屏幕显示：

「品牌方向与首页设计对齐」

两位负责人面对彼此或面向讨论屏。

当讨论产生需要人类决定的重大问题时，右侧 UI 弹出审批卡片。

这里的讨论是 Agent 工作关系的空间表达，不意味着系统必须真的组织一场有语音的会议。

## 07. 休息与待命区

休息区要成为真正吸引人的空间，而不是一张简单沙发。

建议设置约 25–35㎡ 的舒适休闲空间。

配置弧形布艺沙发、小圆桌、植物、温暖的局部灯光、书架和柔和地毯。

可以靠近落地玻璃窗，获得明亮自然光。

这里是 Agent 无任务时的待命空间，也使整个办公室拥有生活感。

负责人可以在待命区以静态姿势停留。

不需要模拟睡觉、喝咖啡、呼吸等细节。

### 接待入口

接待区与休息区相邻，但功能上独立。

设置简洁品牌接待台和 Agent Office 标志，营造进入一座 AI 工作世界的第一印象。

接待台不必常驻接待员工。

未来可承载新用户引导、组织初始化或创建首个目标等产品功能。

## 08. 成果展示区

成果区建议位于主镜头前方偏右的位置。

不使用简单的文件柜或普通工作台，而采用具有品牌记忆点的弧形成果展台。

展台可以展示少量立式成果卡，例如品牌方案、网站原型和验收摘要。

当目标完成时，成果台柔和亮起，用户可以点击查看详细内容。

成果台是 3D 导航入口，真正的报告、代码、图片和证据仍在 2D 详情界面展示。

### Practice 的表达

Goal → Team → Practice 是产品核心模型，但 Practice 不需要永久占据一整座建筑。

当本次成果经过相应验收后，界面可以提出：

「要不要保存这次工作团队和工作方法？」

用户确认后，将团队配置、权限、目标模板和已验证的工作方法保存到工作方法库。

之后再次创建类似任务时可以复用。

在 Mock 演示中，必须明确标记这是模拟验收，不宣称已有真实交付证据。

## 09. 整体建筑和美术规范

### 视觉风格

延续 A1.1「温暖智能工作室」。

以奶油白、浅木色、雾蓝灰、青绿色为基础，使用柔和的黄铜细节和自然光。

保留圆润的建筑轮廓、半透明竖纹玻璃、低矮绿植与精致家具。

避免大量霓虹灯、赛博朋克风格、玻璃全息大屏和夸张的发光路径。

### 材质层次

以哑光材质为主，木材和织物提供温暖感，金属细节增加精致度，玻璃提供通透的空间层次。

每个区域只安排少量重点材质，不依靠装饰数量制造高级感。

### 灯光

整体采用明亮、温暖的白天光线。

只有目标激活、任务交接、审批与成果交付等事件使用局部强调光。

不建议整个地面持续出现发光线路。

### 建筑特色

最有辨识度的元素应当是：

- 一体化的大弧形空间边界。
- 中央目标中枢。
- 多个精致但相互开放的工作岛。
- 自然绿植构成的空间缓冲。
- 具有统一形态的成果展示装置。

## 10. 2.5D 主镜头与交互层次

由于未来我们要在工作空间内展示不同数量的 Agent，建议支持三级观察方式。

### Level 1：世界总览

用户第一眼看到整个 AI 工作园区。

清楚识别目标中枢、各部门、协作区、休息区和成果区。

人物不需要很大，但关键负责人必须有辨识度。

### Level 2：区域聚焦

点击某个工作岛后，镜头平滑靠近。

用户看清部门负责人、当前任务、执行终端和成果状态。

### Level 3：工作详情

点击人物、终端或成果后，打开 2D 面板。

查看真实或 Mock 的任务详情、执行记录、证据和决策操作。

**3D 负责理解空间与关系，2D 负责准确阅读、编辑和决策。**

桌面端优先使用 16:9 布局，并为右侧详情面板预留空间。

不要求主镜头在完整办公园区中直接读清所有屏幕上的小字。

## 11. 核心动态体验：空间如何随目标变化？

以「制作品牌网站」为例。

**状态一：空闲**

负责人在休息区或待命位置。

部门区域保持安静，执行终端息屏，中央目标中枢显示准备状态。

**状态二：目标建立**

用户输入目标。

中央目标中枢显示目标，设计岛和研发岛被推荐并激活。

**状态三：组织形成**

两位负责人前往各自工作区，系统按模拟任务分工激活需要的子 Agent 执行终端。

**状态四：并行工作**

研究、视觉、前端等终端显示当前任务。

各区域只展示少量重要工作状态，不制造大量同时闪烁的信息。

**状态五：协作与讨论**

两个负责人前往讨论区，任务信息发生交接。

**状态六：等待人类决定**

出现需要用户判断的事件，工作流暂停。

中央目标中枢变成等待状态，右侧显示具体审批内容。

**状态七：成果交付**

审批通过后，模拟执行继续，成果最终进入成果展台。

**状态八：沉淀工作方法**

系统建议保存已验证的团队配置与工作方法，以便以后复用。

这条体验应成为未来 M1 和 M2 的共同视觉叙事基础。

## 12. 技术落地原则

B2.0 不能只是一张精美概念图。

实际制作应当将场景拆分为可复用的资产模块：

- 目标中枢
- 标准工作岛建筑
- 负责人工作舱
- 子 Agent 终端
- 协作讨论家具
- 休闲待命家具
- 接待台
- 成果展台
- 通道、地面、灯光和环境装饰

继续使用 Tripo + Codex + Blender + R3F 技术路线。

Tripo 更适合生成单独的高品质家具、道具和局部模块；整体空间布局、关键动线、相机和交互锚点应该由 Blender 与代码共同保持可编辑。

避免直接把整张概念效果图通过图生 3D 转换成一个不可分割的高面数大模型。

## 13. M1 和 M2 的边界

### M1：只建设必要的可运行区域

优先实际完成：

- 目标中枢
- 品牌设计岛
- 研发岛
- 子 Agent 执行区
- 讨论区
- 休息待命区
- 成果交付区

研究策划岛和接待区可以先以简化视觉模块存在。

保持已经验证的 Mock 行为逻辑，不重新建设整个业务系统。

### M2：让组织真正可被用户调整

未来再允许用户：

- 从目标创建新的工作团队。
- 调整参与的能力区域。
- 配置负责人 Agent。
- 设置重要授权与人工参与职责。
- 保存、复用和比较不同工作方法。

不要求用户手动绘制复杂的流程节点。

## 14. 最重要的设计验收原则

B2.0 必须满足四个判断。

**第一眼有吸引力**：即使没有任何状态标签，场景本身也应具有优秀的建筑美感。

**区域能被识别**：不用阅读大量文字，也能通过空间形态区分工作、讨论、休息和交付。

**工作关系能被理解**：用户能看出负责人、执行终端、部门协作及目标中枢之间的联系。

**可以真正运行**：空间可拆分、人物有可用动线，后续能承载动态组织，而不是只能生成一张效果图。

最终目标：

**这不是一间摆放 AI 角色的办公室，而是一座会根据用户目标组织工作的 AI 原生创意园区。**
